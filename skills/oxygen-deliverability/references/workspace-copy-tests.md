# Workspace copy tests

Use Analytics → Deliverability → **Test all mailboxes**, selecting a Sequence and email step to import its copy variants, or `oxygen deliverability workspace-test run --input test.json --json`. Use connected Google/Microsoft mailboxes in the active workspace or the participating network below; no paid seed provider.

Always use realistic prospect outreach, preferably the actual Sequence step. Never substitute “deliverability check”, “test email” or “no reply needed” copy: its landing says nothing about the campaign copy. Keep diagnostic identifiers in native metadata, never add visible test labels. Resolve personalization, preserve subject, text/HTML, links, signature and tracking, and review the frozen preview.

The JSON needs `sender_mailbox_ids`, `receiver_mailbox_ids`, and `variants` containing unique `key`, `subject`, `body_text`, and optional `body_html`. One to five variants and at most 50 messages after excluding self-sends. Resolve every personalization variable first. `workspace-test copy <sequence-id> --step-index 0 --json` reads an email step and its variants for editing. Import copies templates, not an enrollment or campaign launch; review the exact subject, links, text and HTML you supply. Sender signatures appear in the preview. Sequence import also supplies its open/click settings; those use the verified workspace tracking domain and the normal native renderer. Preview reports whether tracking is enabled. Diagnostic opens and clicks do not affect campaign analytics.

Preview sends nothing and costs 0 credits ($0). Show the exact copies, senders, receivers, message count and any missing permissions. After explicit approval, reuse the input with `--approved --request-id <preview-request-id> --plan <preview-plan-hash> --rendered-at <preview-rendered-at> --max-live-sends <message-count>`. Never invent approval. `--allow-paused-probe` must be included in the reviewed preview and approval to permit diagnostic sends from paused senders; it does not resume them. Suppressions and send permissions still apply. Newly approved same-workspace tests have a separate allowance of three sends per mailbox per UTC day, without consuming campaign capacity. Sends are spread across roughly thirty minutes per daily batch; excess probes continue on later days. Preview times are estimates, reserved at approval and rechecked at dispatch. Existing runs and network/staff tests retain their previous capacity contracts.

Read `workspace-test list --json`, following `--cursor <next_cursor>`, then `workspace-test get <id> --json`. Saved reads send nothing, charge nothing and do not poll a provider. MCP: `oxygen_workspace_placement_run` previews/submits; `oxygen_workspace_placement_read` with action `list`, `get` or `copy` reads saved results or copy. They are available in the `placement` pack and native discovery. Follow result cursors with `get <id> --cursor <next_cursor>`. Read the frozen subject and sender name on each probe; `get <id> --probe <probe-id> --part body_text --offset 0 --json` reads its saved text, and `--part body_html` reads escaped HTML source. Follow `next_offset` with `--offset`; `--copy-limit` is 1–3000 Unicode characters. Web provides **Read saved copy** without loading images or opening the received email.

MCP automatically pages large previews: `preview_kind=manifest` includes probe metadata and a cursor. Call run again with the same input, `request_id`, `rendered_at`, and `preview_cursor`; use `preview_probe_id`, `preview_part`, `preview_offset` and `preview_copy_limit` to read each frozen copy. CLI has the corresponding `--preview-*` options. Every page retains the same plan hash; if it changes, review again. Omit all preview paging options on approval. Saved MCP reads accept `cursor`, `limit`, `probe_id`, `body_part`, `offset` and `copy_limit`. Do not approve until every recipient and copy has been reviewed.

Gmail Primary requires explicit provider category evidence; Inbox alone is insufficient. Preserve Promotions, Social, Updates, Forums and unknowns. Microsoft Inbox/Junk and Focused/Other are separate dimensions. Compare each variant's observed/planned counts and per-receiver rows, not percentages with different denominators. The first matching observation is recorded without opening, moving, rescuing or replying to mail.

Queued sends remain pending. The two-hour not-observed deadline starts at confirmed submission. Distinguish unobserved mail, blocked receiver access, failed send and uncertain send. Retry the same approved request ID to read its existing batch; never create another test to recover an uncertain send. Internal tests are directional evidence from known receiving accounts, not a campaign placement guarantee or permission to resume campaigns.

## All mailboxes

`oxygen deliverability workspace-test bulk run --input test.json --json` previews every eligible workspace sender, independently of web filters and pagination. The input contains `variants` and optional `receiver_providers` (Google and Microsoft by default); omit `receiver_scope`, `sender_mailbox_ids` and `receiver_mailbox_ids`. Each sender/copy uses one rotating receiver per provider, excluding self-sends. Review `provider_directions` for all four Google/Microsoft combinations, skipped senders and missing receiver coverage.

Bulk approval uses the same request ID, plan hash, rendering time, input and aggregate `--max-live-sends`. Each child has at most 50 probes; the approved aggregate may exceed 50. Read `scheduling`, `schedule_summary` and each probe's `scheduled_at` for the daily allowance, sending window and estimated final send; observations arrive after sending. Use `oxygen deliverability workspace-test bulk list --json` and `oxygen deliverability workspace-test bulk get <id> --json` for saved results. MCP uses `mode=bulk` on the same run/read tools and the same preview/approval contract.

## Participating receiver network

Use `receiver_scope: "network"` and omit `receiver_mailbox_ids`; `receiver_providers` defaults to `["google", "microsoft"]`. Each sender/copy gets one receiver of each requested provider, rotating across the bounded pool (two messages per receiving mailbox/day). The 50-message ceiling and sender/shared limits remain. Preview and approve exact copy/request/hash/rendering time/ceiling: actual copy reaches another customer’s Gmail/Outlook and can be read there. Preview and results anonymize foreign receivers.

`deliverability workspace-test network` reads participation. Administrators use `--enabled true --accept-disclosure` to accept the current participation/privacy disclosure or `--enabled false` to opt out. MCP: `oxygen_workspace_placement_read` action `network` reads; `oxygen_workspace_placement_run` operation `participation` with `network_enabled` and `accept_network_disclosure` manages it. Participation defaults on; eligibility requires current disclosure acceptance. Participation never starts recurring sends. Opt-out stops further selection, dispatch and observation under the grant.

Verified diagnostics are hidden from both Uniboxes, ordinary message reads, search, counts and reply processing. They remain in provider mailboxes and test evidence. Unknown categories remain unknown; network observations are directional, never a campaign guarantee.

## Staff named receivers

Oxygen staff can use `receiver_scope: "staff"`, `receiver_environment: "dev"` or `"prod"`, `receiver_workspace_id`, and exact `receiver_mailbox_ids`. Discover receivers with `oxygen deliverability workspace-test receivers --receiver-environment dev --json`, adding `--receiver-workspace <uuid>` to list its mailboxes. Sender mailboxes belong to the active workspace/environment. Preview and approve the exact matrix as above; changing environment or workspace changes approval. Staff history is private, with no customer participation prompt or notification. Provider copies remain in Gmail/Outlook. Both environments must run compatible bridge code for remote tests.
