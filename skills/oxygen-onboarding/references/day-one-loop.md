# Day-1 loop (Network Mining, dev)

Only where Network Mining runs: the First leads answer then carries `network_mining`, and `plays.leads` starts with a `focus` read once the CRM holds people. Elsewhere none of this exists; follow [bounded launch](bounded-launch.md).

1. **Focus list.** The `focus` read (its exact CLI and MCP call are in `plays.leads`) ranks CRM people warmest first, then ICP fit, then recent inbound intent. Cite each lead's `reasons` and their evidence ids in `why_warm`, write the fit as `strong: …` or `possible: …` in `icp_fit`, and name `knownBy` when a teammate can introduce. Save about ten with `plays.save`.
2. **Loop columns.** `oxygen onboarding activation first-leads --activation-id <id> --json` (MCP `oxygen_onboarding_activation_first_leads`) adds two columns to First leads and answers what it did in `network_mining`. `person` binds each lead to one record. `opener` drafts the first message from that person's CRM brief in the activation sender's voice; it waits for the sender (`opener_column.status: waiting_for_sender`), so link the sender first. Any other `status` names what blocks the loop. Calling it again refreshes the funnel and the **Day-1 funnel** Dashboard it links (`funnel.dashboard`); `funnel.breakdown.cells` splits it by source × focus decile × sender, each lead in one cell.
3. **Bind.** Run `person` with `oxygen columns run <table> person --json`. Binding is free. When it creates Audience contacts for cold leads (`on_no_match: create`), it previews and needs the user's approval.
4. **Draft.** Run `opener` the same way. The preview quotes its credits, and it runs after the user approves that cap. Every draft becomes a message review. A draft states only facts the brief cites; `why_warm` and the ICP steer it but are never stated as facts about the lead, so reject a draft that does.
5. **Approve.** The user accepts or rejects each draft (`oxygen reviews next --json`, then `oxygen reviews accept <id> --json`; MCP `oxygen_reviews_next`, `oxygen_reviews_decide`; or the web Message review). Only a person can accept. Agents may reject and re-run a draft. A Sequence never sends a draft no person accepted, and holds those leads instead.
6. **Sequence.** Author the guided LinkedIn Sequence ([bounded launch](bounded-launch.md)) with its message `template` set to `{{opener}}`. Enroll only after step 5: an enrollment keeps the copy it was enrolled with, so the enroll answer lists a lead whose draft is empty or not yet accepted under `held_for_review` instead of enrolling it. Enroll those again once a person accepts their drafts, then preview the launch.
7. **Launch.** Only a person starts it: in the web app, in a CLI signed in with `oxygen login`, or by clicking the Copilot card. An Agent run, a workspace API key or Auto-approve gets `sequence_launch_person_required`, so hand the preview to the user.
8. **Standing approval (optional).** To let later leads go out without a review each, a person reviews a batch of at least 10 drafts (`oxygen sequences standing-approval <seq> --json`, then `--approve-batch <preview_hash>`), makes the first launch, then grants `--approve-standing <preview_hash>`. It holds while the Sequence's sources, rules, sender, copy, voice, schedule and caps stay as approved; each draft still passes an automatic check. Any change needs a person again.
